● Both commits are on master:

  - ad3690d has only the BOM fix and its test.
  - c9a2b9a makes every CSV problem exit with code 2 and a
    one-line message instead of a traceback:
  tally: error: argument csv: invalid bank CSV 'thousands.csv':
  line 2: invalid amount '1,234.00'

  How it works: the CSV is now loaded by a csv_arg validator on
  the command-line argument, the same way --rules already is. So
  a bad file is handled like any other bad argument: the usage
  line, the message, and exit code 2. In ledger.py, read_entries
  raises a new CsvError that includes the line number.

  Problems it catches:
  - a missing or unreadable file
  - a file that isn't UTF-8
  - an empty file, or missing date/description/amount columns
  - rows with too many or too few fields
  - bad dates
  - blank or NaN amounts
  - oversized fields, the one csv-module error that can still
    happen

  Checks: 12 new test cases. Formatting and lint are clean, and
  all 48 tests pass. Run by hand, a missing file, "1,234.00",
  and a short row each exit 2 with the message, and
  september.csv still gives the same totals.

  Things to know:
  - 1,234.00 is rejected, not read as 1234.00. That's how I read
    your request. If you'd rather tally ignore the thousands
    separator, it's a small change, but it would guess wrong on
    files that use a comma as the decimal point (1.234,00).
  - Unquoted 1,234.00 shows up as "too many fields", because the
    comma splits it into an extra column.
  - NUL bytes aren't rejected. I first tested for them, but
    Python 3.11 and later reads them without complaint.
  - I updated CLAUDE.md so its architecture notes mention
    csv_arg and CsvError.
