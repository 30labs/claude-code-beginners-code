● I've added tally_mcp.py, an MCP server over stdio with the one
  tool spending(month, csv_path='bank.csv',
  rules_path='rules.toml'), plus tests. Format, lint and all 75
  tests pass. I also ran the real server over stdio: for 2026-08
  against the sample data it returns housing 1450.00, groceries
  217.60, utilities 96.30, transport 40.00.

  How it's put together
  - Dependency: uv add mcp installed version 2.2.0. In 2.x the
    SDK renamed FastMCP to MCPServer (in mcp.server.mcpserver),
    so older examples online won't import as written.
  - Reuse: the calculation is ledger.in_month plus
    ledger.by_category. For checking input I reused month_arg,
    csv_arg and rules_arg from tally.py, so the server rejects
    exactly what the CLI rejects, with the same error messages.
  - Errors: bad input raises the SDK's ToolError. In mcp 2.x any
    other exception is hidden from the client, which only sees
    "Error executing tool spending". With ToolError, the model
    gets a useful message such as "invalid month '2026-13',
    expected YYYY-MM".
  - Output: the tool returns {category: amount} ordered biggest
    first, with amounts as strings like "1450.00". Decimals
    don't convert to JSON exactly, and strings avoid float
    rounding. An empty month returns {}.

  Tests are in test_tally_mcp.py. They call the function
  directly and check:
  - the category totals, their order, and the uncategorised
    bucket
  - an empty month
  - the default paths
  - each kind of bad input

  Two more tests go through server.call_tool: one checks the
  structured output, the other that the error message reaches
  the client.

  Relative paths: the defaults bank.csv and rules.toml are
  looked up in the server's working directory, which is wherever
  the MCP client starts it. Point the client at the project
  folder, for example:

  {"command": "uv", "args": ["run", "--directory", "/tmp/tally",
  "python", "tally_mcp.py"]}
